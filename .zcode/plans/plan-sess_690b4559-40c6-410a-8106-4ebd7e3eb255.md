# Phase 1 收尾批：响应式完善 + 完整状态 + Staging 联调

范围边界不变（Shell + 真实 API + 响应式 UI + 权限状态），仅部署 Staging 验证，不触碰 Production。已确认两项决策：**开放 owner 只读视图**（非 admin 登录用户仅见自己的问卷，403 可真实触发）；**bot /admin 加 WebApp 登录交接按钮**。

## A. 后端 `src/index.ts`

1. **鉴权语义调整（owner 视图）**：`src/index.ts:203` 当前把非 admin 全部 401。改为：`!user`（users 表无记录）才 401；认证通过的用户均放行，`isAdmin` 决定数据范围——dashboard/surveys 已有的 owner 过滤分支（:208-224）随之激活，detail 越权 403（:225）保持。
2. **移除死分支**：`:69-71` 中 `/admin` 前缀下判 `/api/` 前缀的分支不可能命中，删除，保留 `env.ASSETS.fetch`。
3. **`verifyTelegramWebAppUser` 加固**（:229-249）：initData 先 `decodeURIComponent`（配合前端编码）；新增 `auth_date` 新鲜度校验（超过 24 小时拒绝）；导出函数供单测。

## B. Bot 端登录交接

## C. 前端 `admin/dist/index.html`（整理为可读结构，仍无构建）

## D. 前端 `admin/dist/app.js`（整理为可读结构，React UMD + createElement 不变）

1. **Telegram WebApp 集成**：`ready()` + `expand()` + headerColor。
2. **initData 编码修复**：header 值 `encodeURIComponent(initData)`（当前用户名含中文时 fetch 直接抛错）。
3. **Staging Test Header**：挂载时 fetch `/health`；`environment==='development'` 且无 initData 时顶部显示测试条——输入 Telegram user ID → 写 `localStorage.telegramUserId` → 重新拉取；显示当前模拟身份，可清除；生产不渲染。

5. 状态完善：401（"请通过 Telegram 打开管理后台"）/403/404/网络错误区分文案；重试改为重新发起当前请求（非整页 reload）；空态区分「还没有问卷」vs「没有符合条件的问卷 + 清除筛选」；Loading 用骨架屏。

## H. Staging 验证流程（实现完成后执行）

1. secrets：`wrangler secret put -c wrangler.staging.toml`（BOT_TOKEN 复用生产 bot token，initData 签名兼容；WEBHOOK_SECRET、ADMIN_IDS 含测试账号）。
2. 数据：`wrangler d1 migrations apply telegram-survey-staging-db --remote`（staging 新库建表）+ 测试用户入库。
3. 部署：`npx wrangler deploy -c wrangler.staging.toml`。
4. 浏览器验证：/health → Test Header → 身份切换 → Dashboard/List/Detail、搜索、筛选、空态、401/403/404；DevTools 三档视口 + 手机真机。
5. Telegram 真机：临时 setWebhook 指向 staging → /admin → WebApp 按钮带真实 initData 验证 → 验证后切回 webhook。
6. 全程不执行生产 deploy、不读写生产 D1/KV/Queue。
