# quest 扩展包创作指南（写给写剧本的人）

> 不用会写代码。你只需要编辑两个 JSON 文件、准备几张图，打一个 ZIP 压缩包，
> 交给管理端导入，就是一个可以上架的剧情小游戏。字段写错不会被静默忽略——
> 导入器会精确告诉你哪个字段、错了什么。

## 一、快速开始（三步）

1. 新建一个文件夹，放入下面「最小可玩包」的两个文件；
2. 按你的剧情改文字（id 规则见下文，其它随便改）；
3. 打包成 ZIP，交给管理端导入：**/admin → 挑战任务 → 导入扩展包**。

### 最小可玩包（复制即用，两个文件，无图片）

`manifest.json`：

```json
{
  "formatVersion": 1,
  "id": "my-story-001",
  "title": "我的第一个剧本",
  "author": "你的名字",
  "description": "一句话简介，显示在任务包列表里。",
  "adult": false
}
```

`quest.json`：

```json
{
  "version": 1,
  "title": "剧本内标题",
  "intro": "点进包第一眼看到的开场语，最多 200 字。",
  "start": "wake",
  "items": [],
  "nodes": [
    {
      "id": "wake",
      "speaker": "旁白",
      "text": "你在长椅上醒来。面前有两条路。",
      "choices": [
        { "text": "往左走", "goto": "left-end" },
        { "text": "往右走", "goto": "right-end" }
      ]
    },
    {
      "id": "left-end",
      "text": "左边是一条安静的小路，你走完了它。",
      "endingTitle": "小路"
    },
    {
      "id": "right-end",
      "text": "右边是热闹的集市，你逛到了天黑。",
      "endingTitle": "集市"
    }
  ]
}
```

这已经是一个可导入、可通关、有两个结局的游戏。下面的章节再逐个讲进阶功能。

## 二、包的结构

```
你的剧本/
├── manifest.json   必须有：包的名片（名字、作者、分级）
├── quest.json      必须有：游戏本体（剧情、选项、道具）
└── assets/         可选：图片（≤20 张，单张 ≤2MB，png/jpg/jpeg/webp/gif）
```

打包成 ZIP（整个 ZIP ≤8MB）：

```bash
cd 你的剧本
zip -r ../my-story-001.zip manifest.json quest.json assets
```

没有图片就省掉 `assets`。Windows 上选中这几个文件右键「压缩为 ZIP」也可以，
注意 ZIP 里要直接看到 manifest.json，不要多套一层文件夹。

## 三、manifest.json：包的名片

| 字段            | 必填 | 规则                                                                              |
| --------------- | ---- | --------------------------------------------------------------------------------- |
| `formatVersion` | ✓    | 固定写 `1`                                                                        |
| `id`            | ✓    | 包的唯一英文标识：小写字母/数字开头，只能含 `a-z 0-9 _ -`，≤32 位。不同包不要重名 |
| `title`         | ✓    | ≤60 字。任务包列表里显示的名字                                                    |
| `author`        | ✓    | ≤40 字，你的署名                                                                  |
| `description`   | ✓    | ≤300 字，一句话卖点                                                               |
| `adult`         | ✓    | `true` 时答题端先弹 18+ 确认                                                      |

## 四、quest.json：游戏本体

顶层五个固定字段：

```jsonc
{
  "version": 1, // 固定
  "title": "剧本内标题", // ≤40 字
  "intro": "开场引言", // ≤200 字
  "start": "起始节点的 id", // 玩家从哪开始
  "grades": { "s": 90, "a": 70, "b": 50 }, // 可选：评级线（百分比），默认 90/70/50
}
```

### 节点（nodes）——剧情的每一幕

全包最多 60 个节点。每个节点 = 一幕：一段文字 + 若干选项；**没有选项的节点
就是结局**（至少要有 1 个结局）。

| 字段                         | 必填 | 规则                                                                                  |
| ---------------------------- | ---- | ------------------------------------------------------------------------------------- |
| `id`                         | ✓    | 全包唯一，同 manifest 的 id 规则                                                      |
| `text`                       | ✓    | ≤600 字，本幕正文                                                                     |
| `chapter`                    |      | ≤16 字，对话框上的章节名                                                              |
| `speaker`                    |      | ≤16 字，说话人名牌                                                                    |
| `image`                      |      | 配图。写 `asset:文件名` 引用 assets/ 里的图（导入时自动换成站内地址），或 `https://…` |
| `choices`                    |      | 选项数组（≤6 个）；**不写 = 结局**                                                    |
| `endingTitle` / `endingNote` |      | 结局标题 / 评语，只在结局节点生效                                                     |

### 选项（choices）——玩家的每次抉择

| 字段          | 必填 | 规则                                                       |
| ------------- | ---- | ---------------------------------------------------------- |
| `text`        | ✓    | ≤80 字，按钮上的字                                         |
| `goto`        | ✓    | 去哪个节点（必须指向存在的 id）                            |
| `score`       |      | 0–20 的加分，可省略                                        |
| `give`        |      | 玩家获得哪些道具，如 `["clue-photo"]`（最多 3 个）         |
| `requireItem` |      | 门控：没持有该道具时这个选项**锁死**（按钮显示所需道具名） |

### 道具（items）——三种用途

全包最多 24 个。`kind` 决定道具的行为：

| kind          | 行为                                        | 典型用法         |
| ------------- | ------------------------------------------- | ---------------- |
| `key`         | 自身无特效，配合选项的 `requireItem` 做门控 | 钥匙、工卡、请柬 |
| `clue`        | 结局屏**列出来**给玩家看                    | 照片、信件、证词 |
| `collectible` | 每枚 **+2 分**并计入结局的「收集 n/m」      | 硬币、贴纸、徽章 |

道具字段：`id`（唯一）、`name`（≤24 字）、`icon`（一个 emoji）、`kind`（三选一）、
`desc`（≤120 字，结局屏/道具栏里显示的说明）。

## 五、计分与评级（写剧本前要想清楚的一件事）

- 同一个选项**只有第一次经过才计分/发道具**——玩家绕回路刷不了分，所以放心
  让他们自由探索、随意走回头路；
- 评级 = 实得分 ÷（所有选项的 `score` 之和 + 收集品总数 × 2），再按 `grades`
  的百分线定 S/A/B/C（不写就是 90/70/50）；
- 因此 `score` 不影响「能不能通关」，只影响评级。想鼓励探索，就把「仔细看 /
  多问一句」这类选项设为加分项；
- `requireItem` 不限于 `key`——收集品同样能当门控（参考示例包《旧宅寻猫》：
  用小鱼干锁「引猫」的选项）。

## 六、常用结构套路

- **大厅回溯**：起点是「大厅」，四周各开一条支线，支线末尾用「回到大厅」指
  回来。玩家在支线里拿钥匙/线索，最后回大厅开被锁的真结局；
- **分支钥匙锁真结局**：普通结局随便到；真结局的选项加 `requireItem`，钥匙
  藏在支线深处用 `give` 发放（《午夜站台》的检票员名牌）；
- **收集催探索**：3–4 枚收集品散在死角，收集数直接进结局屏，收集越全评级
  越高；
- **每个岔路都要有出口**：节点的选项要么通向结局、要么能走回来。一个「进了
  就出不来又没选项」的节点会被当成意外结局。

## 七、导入器会拦下什么（写错时的报错对照）

导入时任何结构错误都会被拒绝，报错会指明字段。常见对照：

| 报错关键字                             | 原因与改法                                            |
| -------------------------------------- | ----------------------------------------------------- |
| `id 不合法`                            | id 用了大写/中文/空格/超 32 位，或没以字母数字开头    |
| `…超过 N 字上限（当前 X 字）`          | 对应字段超长，删减到上限内                            |
| `goto 指向不存在的节点`                | 选项的 `goto` 拼错了，或节点忘了写                    |
| `requireItem / give 指向不存在的道具`  | 道具 id 拼错，或 items 里忘了定义                     |
| `至少需要一个结局节点`                 | 所有节点都有 choices；把最末节点删掉 choices 改成结局 |
| `start 指向不存在的节点`               | `start` 拼错                                          |
| `kind 必须是 clue / collectible / key` | 道具 kind 拼错                                        |
| `formatVersion 必须是 1`               | manifest 的版本号写错                                 |
| 图片相关报错                           | assets 超 20 张 / 单张超 2MB / 格式不在白名单         |

## 八、发布前自查清单

- [ ] 所有 `id` 全部小写且互不重复；`goto`、`requireItem`、`give` 指向的东西都存在
- [ ] 至少一个结局；从 `start` 出发每个结局都走得到
- [ ] `asset:` 引用的文件名与 assets/ 里的文件**完全一致**（含大小写）
- [ ] 每个节点的选项要么到结局、要么能回来，没有死胡同
- [ ] 各字段没超上限（最容易超的：节点正文 600、选项文字 80、开场 200）
- [ ] 18+ 内容记得 `manifest.adult = true`
- [ ] ZIP ≤8MB、图片 ≤20 张且单张 ≤2MB
