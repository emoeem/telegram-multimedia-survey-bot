# Survey Platform 2.0 产品审计与本轮优化

> 2026-09-18。基于当前代码、真实问卷 JSON、Admin 编辑器、导入链路与结果报告链路检查。

## 结论

平台当前已经具备完整的问卷生命周期：创建、编辑、导入、发布、填写、答卷、结果卡、报告、模板、版本与管理。

本轮重点修正了一个产品层面的错误：**填写者报告不能把普通数字字段或任意长文本自动解释成“人格/能力分析”。**

报告应先区分“用户自己的结果报告”和“创建者的数据统计报告”。前者面向单个填写者，后者面向问卷创建者。

## 真实问卷观察

`personal-profile-survey.json` 是 28 题个人档案问卷，包含姓名、年龄、身高、体重、城市、职业、穿衣风格、情感状态、性格标签、兴趣、生活节奏、长文本自述、照片、语音和文件。

它不是评分测试。因此年龄、身高、体重等数字必须作为个人资料事实展示，而不是伪装成“得分”。照片应进入个人展示/影集，长文本应保留原问题标题。

另一个 `survey.json` 是 93 题情景问卷，主要为单选题并包含长文本。该类问卷也不应因为存在长文本就自动生成“Core Personality”等未经规则支持的结论。

## 本轮已完成

- 无评分规则时，数字题不再自动进入报告 score/radar。
- 明确识别个人档案型结果，生成 `identity_card` / `personal_profile` 结果语义。
- 个人档案优先使用填写者姓名作为报告标题，并用身份/城市组成副标题。
- 个人档案自动优先使用 `identity` 报告模板（仍允许问卷显式模板覆盖）。
- 普通无评分问卷不再把长文本自动重命名为人格、行为、关系等分析维度。
- 保留已有显式评分报告的兼容行为。
- 编辑器“问卷设置”增加“填写后报告模板”选择，可直接绑定平台/自定义报告模板。
- 编辑器 undo/redo 数据模型同步支持报告模板字段。
- 增加个人档案报告回归测试。

## 编辑器现状与后续方向

当前编辑器已有草稿锁、自动保存、stale 检测、undo/redo、结构树、分页、题目/选项复制、媒体管理和实时预览，核心架构无需重写。

下一阶段应优先增强：题型专属设置面板、批量操作、题目搜索/定位、分页拖拽、导入后直接修复、发布前检查清单，以及报告配置的可视化编辑。

## 导入现状与后续方向

当前导入已经支持统一 JSON、旧结构兼容、URL 导入、PDF 转换产物、媒体、分页、置信度和结构化错误。

下一阶段应增强导入“修复工作流”：问题定位、单题修复、类型覆盖、选项合并/拆分预览、导入前后差异，以及重复问卷检测，而不是继续堆更多解析器。

## 管理现状与后续方向

问卷管理已经具备搜索、状态筛选、分页、状态概览、详情、发布/关闭/归档/删除、版本历史、统计、答卷和模板配置。

下一阶段值得做的是批量管理、最近操作、草稿恢复、模板/复制入口统一、发布前检查与危险操作确认，而不是重做现有生命周期。

## 报告 2.0 产品边界

### Participant Report

用户只看自己的：结果、画像、维度、个人资料、原回答、图片、个性化解释和分享卡。

### Creator Report

创建者查看整体数据：回答量、完成率、选项分布、数值统计、趋势、交叉分析和导出。

两者应共享底层数据，但不共享“产品含义”。

## 本轮继续完成：Participant Report 2.0

- 新增 `participant-report.service.ts`，按真实题型/题干与显式 Result Rule 将填写者报告分类为：个人档案、测评、偏好画像、普通问卷、普通表单。
- 个人档案不再把年龄、身高、体重等数字字段解释成分数；无显式结果规则的普通长文本也不会自动命名为人格/行为分析。
- 报告模板会按结果类型自动选择默认模板：个人档案 → 身份档案，测评 → 数据分析，偏好 → 杂志，普通问卷 → 经典，普通表单 → 完整问答；问卷显式绑定模板仍具有最高优先级。
- Web 报告增加结果类型标签、类型化摘要标题和回答区标题，统一由 ReportViewModel 驱动。
- 增加分类回归测试，确保无评分问卷不会产生伪造的评分语义。

## 编辑器 2.0 本轮增强

- 结构树增加题目搜索，可按题干/描述快速定位长问卷中的题目。
- 支持选择搜索结果后批量设置“必答/选填”，修改仍进入现有 undo/redo + autosave 管线。
- 保留现有草稿锁、stale 检测、预览、题目复制、媒体管理和分页能力，不重写编辑器核心架构。

## 导入 2.0 本轮增强

- 导入 JSON 增加格式化与复制操作，降低手工修复成本。
- 校验成功后自动查询同名问卷并提示潜在重复导入，可直接打开已有问卷核对。
- 保留后端已有置信度、自动修复、结构化 issue 与 URL/PDF 转换链路。

## 管理 2.0 本轮原则

问卷管理继续沿用现有搜索、状态筛选、分页和生命周期操作；本轮优先把“编辑/导入/报告”三个入口串起来，而不是增加危险的批量删除等操作。后续批量归档、复制等操作应继续经过明确确认与审计。
