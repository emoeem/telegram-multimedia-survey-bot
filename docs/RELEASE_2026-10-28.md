## 一、面向管理员（登录后台即可用）

### 📥 批量导入：一次贴一整列链接

入口不变：**工作台 → 导入**。原来的单行输入框换成多行文本框。

- 一行一个链接，空行和 `#` 开头的注释行自动跳过；
- 输入时实时显示「识别到 N 条，重复 M 条已合并」；
- 点「开始导入」后**逐条串行**执行，每条独立显示状态：成功 / 失败（带原因）；
- 一行失败**不会中断整批**，成功的那几条可以单独「在编辑器预览」或「打开问卷」；
- 单批上限 50 条，超出时明确提示「请分两批」，不会静默丢弃。

> 为什么串行：每一行背后都是一次对外部平台（Microsoft Forms / Zoho Forms）的真实
> 抓取，并发只会让目标站先把你限流。50 条串行大约 1–2 分钟。

### 📤 批量导出：不再是单独一个页面

入口在**工作台 → 问卷 → 勾选若干份 → 批量操作栏「导出」**，和「批量归类」
「标为 18+」并排。

- 格式：**HTML / Markdown / JSON**，多选，一次打出；
- **PDF**：点「打印 / 另存为 PDF」会在新窗口生成打印视图并唤起打印对话框，
  多份问卷之间自动分页（`break-after: page`）——一次打印就是一份分页正确的合集；
- 导出的是**完整题目结构**：题型、必答、选项、矩阵列、验证约束
  （`0–200 字` / `选 1–3 项` / `评分 1–5`）都会带上。

原来那个独立的「导出」侧栏项已移除，`/admin/exports` 重定向到 `/admin/surveys`，
旧书签不会 404。

### 🖵 顺带修掉的一个地址坑

后台的 basePath 是 `/admin`。以前访问 `/exports` 这类**漏了前缀**的地址，会被
SPA 兜底吞掉然后静默跳回总览页——页面看起来正常，只是不是你要的那个。现在
18 个后台独有路径段会自动补回前缀：

```
/exports   → 302 → /admin/exports      ✅
/settings  → 302 → /admin/settings     ✅
/s  /plaza /cert  …                    ← 公开页完全不受影响
```

## 二、独立程序：`survey-tool`（可离线用）

不依赖后台、不依赖网络登录，**一个可执行文件，双击就是浏览器界面**。

```bash
./tools/survey-tool/dist/survey-tool-linux-x64            # 启动界面
./tools/survey-tool/dist/survey-tool-linux-x64 --port 9000
./tools/survey-tool/dist/survey-tool-linux-x64 --help     # 命令行模式
```

- 界面里：粘贴多行链接（或把 `.txt` 拖进去）→ 点解析 → 逐条显示标题 / 题数 /
  页数，失败的那条当场给原因 → 勾选格式 → 下载 ZIP；
- ZIP 里除了产物，还落一份 `导出报告.md` 记录失败清单——不是只在前端闪一下；
- **命令行一个参数都不用改**：除了 `--port` / `-p` / `--open`，出现任何其他参数
  就走 CLI，老脚本照旧。

**内核只有一份**：CLI 和 Web 都 import 同一个 `core.ts`，而这个 `core.ts` 直接
复用 Worker 侧的 `microsoft-forms.service.ts`、`zoho-forms.service.ts` 和
`admin/src/lib/survey-export.ts`。后台改排版，重编一次就同步，不会分叉。

三平台产物在 `tools/survey-tool/dist/`（**不进版本库**，`pnpm build:tool` 重新生成）：

| 平台         | 大小   | 验证程度                                       |
| ------------ | ------ | ---------------------------------------------- |
| linux-x64    | 87 MB  | **全链路实跑**（2 份问卷 / 121 题 → 6 个文件） |
| windows-x64  | 111 MB | 交叉编译成功，未实机                           |
| darwin-arm64 | 86 MB  | 交叉编译成功，未实机                           |

PDF 走系统 Chromium 的 `--print-to-pdf`，不打包浏览器；找不到就跳过 PDF 只出其余
格式，不中断。

## 三、修掉的两个门禁阻断（10 月中旬起 CI 一直红）

**① 按钮文字对比度 2.1:1（a11y 阻断）**

`<button class="hotspot-modal-back">` 渲染成白字 + 香槟金 `#d4a574`，axe 报
`color-contrast`。

根因不是配色选错，是**变量名对不上**：主题块提供
`--survey-primary-content: #17141f`（注释里写着「金底深字 6.5:1」），按钮读的却是
`--survey-btn-text`，而后者只定义在 `.scene-editor-preview` 里——答卷页没有那个
祖先，全部回退到 `#fff`。

修法是补回退链，不是给弹层打补丁：

```css
color: var(--survey-btn-text, var(--survey-primary-content, #fff));
```

**② 视觉用例还在找一个已被删掉的主题**

`survey.spec.ts` 仍在点「黑金奢华」，但 10-24 那次主题收敛后只剩
`foxgold(暗金) / dark(暗色) / light(明亮)`，旧的 `luxury` 已进 legacy 映射表。
用例 60 秒超时——这是两个视觉 workflow 双双失败、deploy 被卡住的唯一原因。

顺带：`galgame-playthrough` 的 `beforeAll` 从 60 秒提到 180 秒。25 个素材约 15MB，
CI runner 每次全新环境没有落盘缓存，超时会把整条用例判红，看起来像功能坏了。

## 四、技术与运维

- **新增文件**：`admin/src/lib/import-lines.ts`（纯解析）、`survey-export.ts`
  （纯函数渲染）、`survey-export-run.ts`（动作层，碰 Blob / window.open）、
  `tools/survey-tool/`（12 个文件）。
- **为什么拆三层**：`survey-export.ts` 输出字符串，能在 node 里直接断言；
  动作层单独放，导出逻辑才写得出单测。混在一起就只能靠浏览器验。
- **线上新增的坑（PDF 丢题）**：导入器产出的 `survey.json` 字段是
  `page_id`（字符串 `"p1"`），编辑器接口给的是 `pageId`（数字）。第一版分组只认
  数字，所有题目落进 `null` 桶后被 `if (!bucket.length) return ""` 静默丢弃——
  **28 道题导出成 1 页空白，零报错**。现在统一按 `String()` 比较，且落不进任何
  一页的题目单独渲染成「未分页题目」，永不丢弃；3 条回归测试锁住。
- **批量导入的边界**：每行的失败原因来自上游 HTTP 状态与解析结果，不做二次改写；
  去重在后端不做（管理者可能真想导两次），只在前端提示。
- **导出接口**：复用既有 `export.service.ts`，本轮只在 `SurveysPage` 增加动作入口，
  未新增服务端路由。

### 同时上线的其他改动（非本轮验证重点）

`a0f7e7c` 带上了此前积压的**场景编辑器 / 树洞笔记**路由接线
（`SceneEditorPage.tsx`、`EditorPage.tsx`、`note-api.ts`、`note-chat.service.ts`、
`hotspot.ts` 及配套 4 个测试文件，共 +1270 行）。为了让构建能过必须一起入库，
测试、`tsc`、`format:check` 全绿，已随本次部署上线；但**功能正确性没有逐个手验**。
