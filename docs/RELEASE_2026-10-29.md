## 一、答卷者：公开发布前的三选一

提交问卷勾选「公开发布」时，不再是一点就发出去，而是弹窗明确三个选择：

- **是否公开**：公开发布到频道 / 仅自己可见（仅自己可见时随时可改）；
- **是否匿名**：匿名时发布内容（caption + 报告图片）不出现任何 Telegram 身份；
- **想说的话**：附在发布消息里的配文，200 字以内，可空。

两个默认值都是有意选的：**默认不公开、默认匿名**。频道消息发出去就收不回来，
"不匿名"应当是答卷者主动放弃隐私的一次点选，而不是默认结果。老答卷（迁移前
已存在、无从追溯当时意愿的）发布时一律按匿名处理。

匿名在**源头**生效，不是渲染时遮盖：匿名标记传进答卷详情查询时根本不查 users
行，姓名 / `@username` / Telegram ID 不会进内存，下游谁也拿不到。

选择摘要会回显在确认页上（`公开发布 · 匿名 · 留言 12 字`），提交前一眼可见。

## 二、频道发布：修掉三个连锁问题

一份报告可能二十几页，而 `sendMediaGroup` 一次最多 10 张，发布必然分批。原先
的实现有三个后果，这次一起修掉：

1. **caption 只挂在第 1 批**——第 11 页之后的消息在频道里没有任何「哪份问卷 /
   什么时候填的 / 这批是第几页」。现在每批都带。
2. **第 2 批失败会被误标为已发布**——已发出的 message id 非空，发送不抛错、
   照样写 published，频道里只有前 10 页且永远不会补发。现在发送前用一条条件
   UPDATE 抢锁（`report_publication_claim_at`），抢不到说明另一个消费者正在发，
   直接跳过——同一份相册不会并发发两遍，也不会带着半截进度宣称成功。
3. **失败只能整份重发**——现在每批发完写一次断点（`report_publication_progress`：
   各目标的 `nextOffset`），重试从断点续发，已进频道的批次不会重发。

管理端 **答卷详情 → 「重新发布」** 是 `failed` 状态的唯一出口，手动点一下就
从断点继续。

## 三、限流：三处结构性修复

1. **地址未知不再并桶。** 解析不出调用方地址的请求，原先共用 `"unknown"` 一
   个计数桶——「每个地址 20 次/小时」会静默退化成「全站 20 次/小时」，20 个
   匿名访客就能把邮件登录打停。现在这一维度直接跳过并留日志（fail-open +
   observable），覆盖：公开 API、问卷搜索/访问码、媒体上传、抽卡、认证卡分享、
   免登录投稿、邮件登录按 IP 维度。投稿落库的 IP 同步改为地址未知时存 `null`。
2. **RateLimitDO 不再永久空转。** 清扫闹钟原先按「还有没有键」决定要不要重排，
   于是扫完即空的实例每 10 分钟醒来一次、永远醒下去。现在计数器写入
   `expiresAt`，清扫后只在仍有未过期计数器时才重排闹钟。
3. **上传与搜索的限流各自归位**：媒体上传按地址 20 次/分钟（地址未知跳过），
   问卷搜索维持 30 次/分钟。

## 四、机器人主菜单：补上四个网页入口

个人中心（`/me`）、抽卡（`/gacha`）、金币中心（`/coins`）、纸条聊天（`/notes`）
在网页端早就做完了，机器人主菜单里却一直没有。现在四个入口都以 `url` 按钮进
网页，不在 Bot 内重做。用 `url` 而不是 `web_app` 是有意的：`web_app` 只在
HTTPS + 私聊可用，`url` 在私聊/群聊都成立。身份参数缺失时生成无身份链接，
任何情况下都不会拼出 `pt=undefined`。

## 五、顺手修的两个界面 bug

都是发布弹窗把焦点还给复选框之后暴露出来的：

- **提交按钮消失**：「公开发布」复选框此前被当成「正在输入」，底部操作条滑走
  （`translate-y-full`），而复选框不会自己失焦，「提交问卷」就再也回不来——
  用户填完了却找不到提交按钮。现在按 input `type` 排除非输入型控件，任何失焦
  一律解除输入态。
- **弹窗被软键盘压住**：Mini App 在 iOS 上软键盘不缩小 layout viewport，
  `position: fixed` 贴底的弹窗输入框会被压在键盘后面。新增 `visualViewport`
  换算（键盘弹起时把遮罩层缩到可视区域），普通状态交还 CSS 默认值。

另外问卷提交的成功 / 失败加了震动反馈：Mini App 内走 Telegram
`HapticFeedback.notificationOccurred`（iOS 上 `navigator.vibrate` 不存在，这是
唯一会真的震动的一条），普通浏览器走 `navigator.vibrate` 兜底。提交有 5 条失败
路径，此前没有任何触觉反馈。
