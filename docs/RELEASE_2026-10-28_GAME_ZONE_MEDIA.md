# 2026-10-28 更新说明（小游戏区 / 双联动 / 素材库）

## 一、这次上线了什么

四块内容一次排期、分四个里程碑落地，每个里程碑单独可上线：

### 里程碑 1：任务区 → 小游戏区

- `task_packs` 新增 `game_type`（默认 `tower`）与 `settings_json`，玩法类型由
  代码层注册表 `src/trial/engine-registry.ts` 校验（不加 CHECK，新玩法免迁移）。
- 开局入口按玩法分发：未注册的玩法直接拒绝（`unsupported_game`），不再误入爬塔流程。
- 前端/文案统一改名：底部导航「挑战」→「小游戏」，后台「任务包」→「小游戏管理」，
  Bot 主菜单与管理员面板按钮同步；公页面标题改为「小游戏 · 问卷平台」。
- 小游戏首页按玩法分组展示（当前只有「爬塔挑战」一组，分组结构先立起来）。
- **路由 `/trial` 与全部 API 路径保持不变**，已分享出去的链接不会失效。

### 里程碑 2：问卷内嵌小游戏（game 题型）

- 新增题型 `game`：题目配置 `settings.game.packId` 指向小游戏区的一个任务包，
  答题者在问卷页面内直接玩（复用 `/trial` 的服务端开局/商店/结算 API）。
- 答案存为 `{kind:"game", runId, score, grade, completed}`，**分数与评级一律
  服务端按 task_runs 记录重算**——客户端传的 score 会被丢弃（有单测钉住）。
  归属校验：runId 必须属于当前答卷参与者，且属于该题配置的包。
- 剧情联动：通关自动置 flag `game_passed_<题号>`，在 flagJumps 里引用它即可做
  「必须通关才能继续」；answerRules/flagRules 的数值比较会把 game 答案投影成
  得分（未通关为 0）。客户端与服务端引擎同构改动，两边行为一致。
- 必答语义：必答的 game 题以「通关」为作答门槛（弃坑/中断不算完成，可重打）。
- 编辑器新增「互动」题型分组 + 包下拉选择器；预览/答题列表自动适配；
  Bot 端仅展示题面（game 题是网页交互，属于已知限制）。

### 里程碑 3：认证卡动态联动（实时抽取）

- 新增 `GET /api/cert/draw`：按任务包加权抽取（分值作权重，不放回），
  **必须带 `ack=adult18`**，未确认 18+ 一律 403，按 IP 限流（30 次/10 分钟）。
- 抽取服务 `src/services/game-draw.service.ts` 是通用实现：认证卡联动与未来的
  「抽取玩法」引擎共用。
- 认证卡内容包 schema 新增可选 `draw: {packId, count(1–5), label}`；后台
  「认证卡内容」页新增「抽取池」配置段。老内容包无此字段，行为完全不变。
- `cert/app.js`：「帮我选」在主题配置了抽取池且 18+ 门禁通过时改为调服务端
  实时抽取并渲染结果；包不可用/网络失败自动回退现有本地随机（有离线兜底）。
- **一处维护处处生效**：认证卡只存 packId 引用，后台改任务包后认证卡自动跟着变。

### 里程碑 4：素材库 + 全库存储去重

- 迁移 0091：`media_assets.content_hash` + 索引；新增 `media_refs` 弱引用登记表。
- **内容寻址去重**：后台附件、BGM、素材库上传三处统一走 SHA-256 查重，同哈希
  复用既有 asset 行（不写新 blob）；新 blob 的 key 为 `media:blob:<sha256>`，
  R2 层面天然单副本。跨问卷引用同一素材只占一份存储。
- 答卷临时上传（`media:temp:*`，按答卷过期）**刻意不去重**——清理一份答卷
  不能连带删掉别人答卷的同内容照片。
- **Telegram 复用**：`registerMediaAsset` 按 `(file_unique_id, 类型)` 查重，
  同一文件重复发送不再各建一行；Telegram 资产**首次被读取时**下载一次回写 R2
  并翻转存储类型（保留 file_id 兜底），此后与 R2 资产同速，不再每次 cache miss
  都走两趟 Bot API。
- **弱引用结构化**：每日维护任务新增 `syncWeakMediaRefs`，把 `settings_json`
  里的 `media/<id>` 引用写进 `media_refs`；孤儿清扫的候选查询也加了
  `NOT EXISTS media_refs` 保护。存量数据可跑 `scripts/backfill-media-refs.mjs`
  生成 SQL 手动回填。
- **素材库管理页** `/admin/media-library`：分页列表、类型筛选、上传（提示是否
  复用）、复制链接、引用计数展示、零引用才可删（服务端二次校验 + 审计）。
- **编辑器「从素材库选择」**：题目附件上传端点支持 JSON `{assetId}` 分支，
  选中即建关联，不重传文件。

## 三、上线注意

1. **必须先跑迁移**：`0090_game_zone.sql` 与 `0091_media_library.sql`。
   存量任务包自动获得 `game_type='tower'`，无需人工处理。
2. **文本基线**：导航/页面标题改名会改变视觉截图，基线只能在 CI 字体环境
   重生成（本地字体不同，本地重拍会双红）——沿用 HOTSPOT_EDITOR_HANDOVER 的约定。
3. **素材库对存储的依赖**：去重后的 blob 建议在有 R2 绑定的部署上使用；
   纯 KV 部署仍可用（KV 单值 25MB 上限照旧）。
4. **客户部署**：每个客户实例 D1/R2 物理隔离，去重只在该实例内生效。

## 四、已知限制（本次未做）

- **game 题在 Bot 端只能看题面**，必须到网页玩；Bot 向导也不能新建 game 题
  （与管理端 `scene` 题同一策略）。
- **BGM / 场景图仍是 URL 字符串引用**：本次把它们登记进 `media_refs` 让引用
  计数与删除保护能看见，但**写入侧没有改成结构化 mediaAssetId**，避免动场景
  编辑器（HOTSPOT_EDITOR_HANDOVER 明确约束：不改热点 id、scene 不进
  EDITABLE_TYPES、媒体必须挂 question_media）。彻底结构化留作后续专项。
- **回填脚本是单次 SUBSTR**：一份 settings 只处理第一处 `media/<id>`，多引用
  的问卷依赖每日维护任务全量重建（那段是循环抽全部引用）。
- **「抽取玩法」尚未作为独立玩法上线**：本轮只落了抽取服务与认证卡联动，
  爬塔仍是唯一玩法；问答/抽取类游戏包待下一轮按注册表扩展。
- 场景编辑器 / 树洞笔记的生产人工验收、投稿自动审核适配器、媒体字节独立备份
  仍在此前的遗留清单里，本次未触碰。
