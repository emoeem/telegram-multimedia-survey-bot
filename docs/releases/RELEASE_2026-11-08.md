## 投稿墙公开上线

投稿中心（`/submissions`）新增「投稿墙」页签：通过审核的免登录投稿在这里公开展示。
墙的可见性由运营在管理端「网页投稿」页的开关卡片控制，**默认关闭**，本次已开启。

隐私采用**双闸**设计：总开关 + 字段白名单，两把锁都过才出网。默认公开分类、标题、正文、
图片、署名方式、署名；**联系方式（contact）默认不公开**——投稿者留联系方式是给审核跟进用的，
公开墙不属于它的用途，白名单里可以单独放开但默认收紧。署名遵循既有规则：选「匿名投稿」的
作者即使表单里填过昵称也不会署名。投稿前有告知文案（内容默认仅以展示版本公开，撤回后立即
停止展示）。

配套给管理端补了投稿墙的运营入口（此前双闸只能直接改数据库）：总开关 + 字段白名单逐项
开关，改动写入审计日志，下一请求即时生效。

## 树洞举报机制

树洞每张帖子的页脚新增「举报」按钮。举报不走人工翻列表：同人重复举报只计一次，
第三人举报达到阈值后帖子自动隐藏，再由管理端「被举报」筛选处置。单帖举报限流
5 次/小时。同时把功能全景文档里「已有举报」的失真声明修正为与实现一致（弹幕举报
文档口径同步改为未实现）。

## 纸条聊天：举报 / 拉黑 / 通知

- **举报与拉黑**：会话内长按对方消息可「举报此消息」（带理由）或「拉黑对方」；
  头部菜单提供拉黑/解除拉黑。拉黑后输入条变只读。管理端复核页可处置被举报消息。
- **通知可发现**：底部导航「我的」图标加未读红点（轻量计数端点 + 60 秒缓存，
  故意不做轮询，避免免费额度内的请求量放大）；绑定了 Telegram 的参与者收到回信、
  被抽中时会收到 Bot 私信提醒，点开直达对应会话。未绑定 Telegram 或无法识别接收方时
  静默跳过，不影响消息本身。

## 修复的隐患（含根因）

- **投稿墙媒体端点绕过隐私闸（高危）**：根因是媒体字节端点只查了发布状态、没有同步
  投稿墙的两个闸位——总开关关闭时已发布投稿的附件仍可按可枚举的整数 ID 拉取。修复后
  未开启或字段未白名单一律 404，与墙投影共用同一把白名单锁。
- **纸条回复测试并发超时**：根因是测试内动态 `import()` 与路由初始化存在竞态，负载下
  偶发 5 秒超时；改为静态引入后消除。
- **文档数字失真**：测试 / 迁移 / 页面数停留在旧版本，README 与功能全景已按实测更新。

## 回滚

```bash
# 回到上一 Worker 版本（秒级，不动数据库）
pnpm exec wrangler rollback

# 或重新部署任意历史提交
git checkout <commit> && pnpm run deploy
```

迁移 `0094`–`0096` 均为纯新增表/索引，不改动任何存量数据；极端情况下回滚数据库
只需 `DROP` 对应新表与索引（`note_message_reports`、`note_blocks`、`plaza_post_reports`、
`plaza_comment_reports` 及排行榜索引），无需触碰业务表。
