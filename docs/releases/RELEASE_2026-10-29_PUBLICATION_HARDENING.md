## 一、隐私：报告图片不再印数字 Telegram ID

上午上线的匿名剥离有一个缺口：caption 走的是公开面标签（只有姓名/@username），
但**报告图片的页眉**还在用管理员私有面的完整格式——实名发布的每一页 PNG 上都有
`Telegram ID: <数字ID>`。数字 ID 可以被 `tg://user?id=` 和第三方工具精确检索到
一个人，答卷者同意公开的是名字，不是它。

现在公开发布路径显式传入公开面标签：匿名渲染「匿名」，实名只渲染姓名/@username
（连用户名都没有就渲染「未知填写者」，绝不拿数字 ID 顶替）。管理员后台看到的
私有报告保持完整格式不变。新增真 SQLite 集成测试钉住这条边界。

## 二、发布锁：修掉三个会真实发生的竞态

1. **锁被占的队列消息不再「跳过即 ack」。** 原先抢锁失败的消息直接确认掉——一旦
   持锁者随后被杀，这份答卷就永久停在 pending：没有队列消息、没有 cron 扫描、
   界面上连重投按钮都没有。现在延迟 150 秒重投（落在 5 分钟锁过期之后），重投
   耗尽才放弃；管理端「重新发布」按钮对 pending 状态也可见。
2. **锁与断点的写入全部加 CAS。** 原先「admin 重投无条件清锁 + 断点写入不带
   条件」意味着：一个消费者正常发布的中途，重投请求可以把它的锁抹掉、第二个
   消费者随即抢锁并发发送——同一份相册进频道两次，断点还会被覆盖回退。现在
   所有断点/终态写入都带 `WHERE claim_at = 本次凭据`，发现锁易主立即停手；
   重投端点只清「无锁或已过期」的锁，锁活跃时明确返回 409「正在发布中」。
3. **长渲染不再把锁「用过期」。** 渲染（等兄弟任务 + 浏览器额度闸门）可能超过
   5 分钟锁 TTL，原先第一个并发窗口恰好开在发送开始的地方。现在渲染完成先落
   一次断点（顺带续锁），之后每发一批续一次——只要发送在推进，锁就不会过期。

## 三、限额：失败提交不再烧「每日 2 次」

公开发布的按身份/按地址日计数原先混在提交的**第一批读**里——漏了必答题、提交
过快、设备超限等被打回的提交也照样烧额度。真实用户连吃两次校验失败，第三次
真正提交就会被 429 拦下，而他当天一条都没发布过。现在计数挪到全部校验通过
之后、入队发布之前：只有真正走到提交的尝试才计数。

## 四、其余修复

- **限流哨兵契约**：跳过限流的占位语句原先返回 `SELECT 0`，而读取兜底把非正数
  钳成 1——注释说「读回 0」、实际全是 1。当下无实害（所有闸门都是 `> 上限`
  形态），但未来任何 `count >= 1` 闸门会把「跳过」变成「全站第一发即中」。
  改为 -1 哨兵 + 显式处理，单测钉死「跳过→0 / 缺失→保守 1 / 正常→原值」。
- **caption 码点截断**：问卷名/填写者截断原先按 UTF-16 切，emoji 恰好压在边界
  上会被切成孤立代理项，Telegram 对整条消息回 400、该批发布失败。改按码点。
- **相册超时**：上传超时按张数放粗（10s + 3s/张，封顶 40s）；超时错误文案标注
  「可能已送达，续发前请先核对频道」——Telegram 没有幂等键，abort 时请求可能
  已经送达，静默按未发处理会让弱网重试发出重复页。

## 五、性能

- **问卷复制**：页/题/题目媒体/选项改为 4 类批量插入。原先 50 题 × 4 选项的
  问卷复制一次要打约 **560 次串行 D1 往返**（机器人与管理后台的「复制问卷」
  都走这条路径），现在是个位数。
- **管理端四处 N+1**：授权列表的激活记录（101 次 → 1 次）、系列列表的章节
  （每系列一次 → 1 次）、抽卡奖池统计（每池一次 → 1 条 GROUP BY）、结局奖池
  生成（逐条 INSERT → 一批）。
- **微优化**：主题消毒的页/题键正则预编译；成就时间的 `Intl.DateTimeFormat`
  提为惰性单例。

## 六、已知取舍

- **相册的「至少一次」语义无法根除**：Telegram sendMediaGroup 没有幂等键，
  「已送达但响应丢失」在物理上不可区分。本轮做的是压概率（超时放粗）+ 可见性
  （错误带「可能已送达」标记），做不到精确一次。
- 管理端 pending 的 409 提示依赖管理员稍后再试；锁最长 5 分钟自动过期。
- 视觉回归基线只能在 CI 字体环境生成，本地不重生成（沿既有约定）。
