## 2. 关键产品变化

### Participant Report

报告现在明确面向填写者本人。个人档案中的年龄、身高、体重等数字是资料事实，不会被自动解释为评分；普通长文本也不会因为长度而自动产生人格、行为或关系结论。

### Result Engine

创建者可以显式配置维度、题目分值、结果类型和总分区间。计算结果由确定性规则产生，报告模板只负责呈现。

### Result Rules 调试器

编辑器提供实时“测试答案”：创建者可以模拟选择题、多选题、是非题和评分题，立即看到维度得分、总分、命中结果和匹配原因。测试答案不会写入真实答卷。

### 报告模板

模板只改变报告结构、布局和视觉主题，不改变答案计算。Admin 模板库增加可视化 schematic preview，Web/PDF/Image 继续共享 ReportViewModel。

### Telegram 归档

归档 ZIP 使用明确目录：

```text
00-index.json
01-report/
02-answers/
03-attachments/
04-profile/
05-result-assets/
```

超过安全发送阈值时自动回退为 PDF + 图片逐项发送。

## 3. D1 成本治理

2026-09-14 曾发生约 5.34M rows read 的异常峰值，触发免费额度风险。根因是维护清扫中的媒体引用检查没有可靠走完整索引路径。

本次修复：

- 补齐媒体引用索引；
- orphan-media 清理执行前检查索引；
- 单次维护读取硬预算 500,000 行；
- 使用 `meta.rows_read` 在步骤间累计；
- 超预算立即停止后续步骤；
- 请求和 Queue 纳入 D1 行读/写指标；
- 公开读取增加 KV cache；
- 降低重试 cron 频率。

## 管理后台登录重构（Telegram Deep Link）

2026-09-18 后续修复：移除依赖 BotFather Login/OIDC 配置的浏览器登录方案，改为 Telegram Bot Deep Link + 明确确认。

登录流程：

1. 浏览器打开 `/admin/login`，点击「使用 Telegram 登录」。
2. Worker 在 KV 创建 5 分钟有效的随机登录请求，并签发 HttpOnly、签名的浏览器绑定 Cookie。
3. 浏览器打开 `https://t.me/<bot>?start=admin_login_<requestId>`。
4. Bot 只允许 `ADMIN_IDS` 中的管理员确认，并展示「确认登录 / 取消」按钮。
5. 确认结果写回 KV；浏览器每 1.5 秒轮询状态。
6. Worker 再次校验 Telegram 管理员身份，签发现有 7 天 `admin_session`，随后进入 `/admin`。

安全与运行特性：

- 登录请求 ID 使用 24 字节随机值，不把 Telegram 用户 ID 放进 URL。
- 浏览器请求 Cookie 使用 `WEBHOOK_SECRET` HMAC 签名，不能伪造请求状态。
- 登录请求只存 KV，不产生 D1 写入，避免登录流量影响 D1 配额。
- 不再需要 BotFather Login/OIDC client id/secret。
- 旧 `/api/admin/auth/browser` bearer-link 入口仅重定向到新的登录页，不再能够直接换取管理员会话。
