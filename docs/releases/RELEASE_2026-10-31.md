## 一、归档频道图片灰块（根因修复）

**现象**：归档频道新作品消息图片是灰色占位，标注「成品 1 张（未上传原图）」。

三个问题三个答案（先复现后动手）：

1. **「未上传原图」哪步断了？** 哪步都没断——前端 FormData 没有 `source` 字段
   的设计分支（用户会话内没往卡上放照片；照片只存内存，刷新即清空）。已补
   诊断日志：原图取回失败不再静默。
2. **图片源是什么？** multipart 原始字节直传 Telegram（`sendPhoto`/
   `sendMediaGroup`），不是 R2 直链也不是 file_id——不存在 URL 过期/跨 bot 失效。
3. **灰块是什么？** TG 收下了字节（caption 完整 = 200）但解不出图。根因：
   cert 前端导出 **WebP**，worker 侧 `readImage` magic-byte 放行 WebP，但
   `telegram.ts` 二进制分支**硬编码声明 `image/png`**——TG 按 multipart 声明
   选解码管线，声明与字节错配 → 灰块。该链路测试覆盖此前为 0。

**修复**：`BinaryPhoto { bytes, type }` 全链路携带真实 mime（缺省 PNG 兼容报告
页调用方），文件名扩展名跟随；补 cert-share 与 telegram 两层单测填盲区。

**待人工确认**：TG 内发一张带 WebP 成品的卡验证灰块消失（无测试频道/生产
token，无法代验）。若个别客户端对 WebP photo 显示仍差，备选 = 导出切 PNG。

## 二、盖章可配置 + 烧录进图片

认证卡生成器新增「盖章设置」：

- **印章文字** ≤8 字（建议值 = 月日+「认证」，可自定义）、**位置** 五预设
  （左上/右上/左下/右下/居中）、**透明度** 20–100%（默认 85%）；
- 配置存 localStorage（`cert-card-maker:stamp-cfg`），重开页面复用；
- 「确认盖章」后印章**直接烧进画布**：预览与导出同一份像素（零偏差），
  「原图保留可重新盖章」由全量重绘保证；
- **为什么用 canvas 而不是 worker sharp**：0 依赖、0 包体、0 延迟，sharp 要
  数 MB wasm + 上传往返，换不来画质差异；
- 动画/音效/震动保留（确认瞬间触发）；版式自带的章是版式设计的一部分，
  用户章是叠加的确认章，两者不冲突。

## 三、后台信息架构工作区化（用户提案落地）

> 用户原话：「为什么最左侧一定要有那么多面板……点问卷这个分类，整个界面
> 就不一样，类似新建一个标签页。创作的时候这些内容完全没用。」

按此重构为两层导航（**路由不变**，只改组织方式）：

- **全局图标轨（56px 常驻）**：总览 + 四个工作区（问卷/内容/社区/系统）各一个
  图标，点哪个进哪个；
- **工作区子导航**：进入后主区域顶部出现该工作区的横向 tab（问卷 = 列表 |
  分类 | 导入 | 答卷动态 | 报告——报告从「内容」组挪入，它是答卷产出的归档），
  其余工作区全部隐去；
- **创作沉浸态**：编辑器/场景编辑器隐藏图标轨与子导航，整宽渲染；
- 手机端保持抽屉，抽屉里列工作区；creator 角色只见问卷工作区（语义平移）。

默认值选择理由：画布默认「列表」形态、结果设计器默认折叠、系统组默认收起——
创作者的主路径（选题型→填内容→导出）全程不需要看到任何高级配置。

## 四、编辑器右栏「结果设计器」（用户报告太乱，根因修复）

用户看到的「乱」三根因全部查实：

1. 360px 右栏塞进了为整页宽设计的双列面板，内层 320px 硬下限把配置列压成
   0 宽——「评分维度 题目→分数→结果」**逐字竖排**成假步骤条；
2. 基础/专业模式对它零门控——没配过评分维度的用户直面全展开空态；
3. 手机端右栏整体隐藏，问卷设置在手机上**没有入口**（提示指向看不见的面板）。

修后：右栏默认只显示设置表单 + 一张「📊 结果设计器 ›」折叠入口卡；点开
单列堆叠（CSS 容器查询，救「宽视口里的窄列」）；基础模式显示「专业模式可用」
引导；手机选中「问卷设置」时表单直接在中栏展开。
