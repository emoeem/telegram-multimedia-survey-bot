## 一、面向参与者（可直接转发到社群）

### 🗂️ 问卷分类：88 份问卷不再是无限长的一列

- 目录页顶部多了一排分类：**情景剧情 · 指令任务 · 调教养成 · 自测评估 ·
  身份反差 · 互动小说 · 个人档案**。
- 点一下就筛，**不刷新、不转圈、不跳回顶部**；再点一次「全部」回到全集。
- 每张问卷卡左上角都标着自己的分类，可以先看分类再决定点哪份。
- 筛选状态写进网址：把「只看情景剧情」的链接发给别人，对方打开就是筛好的结果。
- 手机上分类条是**横向滑动**的，不会折成三行把列表推下去。
- 未确认 18+ 时，只含成人内容的分类不会显示空抽屉。

### 🪪 认证卡生成器：从 13 种扩展到 26 种版式

入口有三个，随便挑一个：底部导航「认证卡」、目录页顶部的入口卡、
`/cert/` 直接访问。

**新增 13 种「证件」版式**（拟真排版，带防伪底纹、微缩文字、钢印、机读码）：

原有 13 种趣味版式全部保留（词云、印章、宾果、化验单、小票、狗牌、
SSR 卡牌、成分表、通缉令、拍立得照片墙、印样联片、资格证等）。

**另有一组成人向证件**（认主契约、畜籍证、识别卡）默认不显示，确认 18+
之后才出现——不确认的话它们根本不在页面里。

### 🔒 认证卡：照片不上传，刷新即忘

- 卡片在**你自己的浏览器里**画出来，照片和勾选内容**不经过服务器**。
- 照片只存在于当前页面内存里：关掉页面就没了，不会留在任何地方。
- **分享链接不包含照片**，只带主题、勾选、姓名和版式——发出去不会泄露你的照片。
- 另有**单文件离线版**，微信里直接打开也能用，不需要联网。

### 🌐 广场与投稿页有了「← 首页」

之前从广场或投稿页进去只能靠浏览器后退键。现在两页共用同一套顶栏，
左上角固定有「← 首页」，手机上点击区按 44px 标准做的。

### 🃏 广场往下滑，不会再把同一张卡塞两遍

现象是连续往下滑的时候，偶尔有一份问卷出现两次、编号重复。

原因是触底加载拿一个「正在加载」的状态位当闸门，而这类状态要等下一次渲染
才看得见；滚动事件和底部哨兵可能在**同一帧**里都读到「没在加载」，于是同一个
游标被请求了两次，第二页整页追加了两遍。机器越快越不容易撞上，手机上反而更容易。

现在闸门是同步的，追加时还会按问卷编号去重。**同一份问卷在广场里只会出现一次。**

## 二、面向创作者与运营

### 管理端 → 分类（新页面）

新建、改名、改网址标识、调顺序、删除，每行显示该分类下有多少份问卷，
点数字直接跳到筛好的列表。

设计上做了两个刻意的取舍：

- **一份问卷只属于一个分类**。多标签会把列表页变成筛选器迷宫，所以是外键
  而不是关联表；空分类 = 「未分类」，公开目录归到「全部」。
- **删分类不会删问卷**：先把问卷解绑（含回收站里的行），再删分类行。
  恢复旧问卷时不会指向一个不存在的分类。

### 管理端 → 问卷列表

- 表格多了「分类」列，未归类的显示为「未分类」。
- 筛选栏多了分类下拉；未分类有独立入口，专门捞漏网的。
- 勾选多份 → 「批量归类…」，一次最多 200 份，写审计日志。
- 窄屏下筛选栏自动换行，搜索框独占一行（之前四个控件挤在一排，
  搜索框被压到 175px，占位符只剩「搜索问…」）。

### 管理端 → 认证卡内容（新页面）

成人向词库的可视化编辑：19 个板块 / 1050 条词 / 9 档强度，可增删改、
按板块筛选、批量导入。这部分内容**不写死在代码里**，运营方自己决定放什么。

### 侧栏：矮一点的屏幕上，入口不再被挤出屏幕

之前侧栏是跟着页面一起长的：窗口矮的时候，最下面那组（审计 / 回收站 /
授权 / 控制中心 / 设置）被推到屏幕外，要滚**整个页面**才能点到——
不是侧栏内部在滚，是它根本没框住自己。

现在的行为：

- **侧栏固定在视口里**，自己滚动，页面滚它就滚不动了。
- **「系统」组默认收起**（最不常用的一组），当前页面在该组里时自动展开。
  「内容」组也可以手动收起，收起状态会记住。
- **窗口高度不够时（≤860px）自动进紧凑模式**：只铺开常用的 `工作台` 和
  `内容` 两组，其余 7 项（开启授权中心后 9 项）和两个快捷入口收进底部的
  「更多」面板，飞出来选。
  **1024×768 的横屏平板和 1366×768 的笔记本都属于这一类。**
- 触屏设备每一行 44px（手指点得准），鼠标设备 40px（一屏看更多）。
- 侧栏底部的环境信息只在手机抽屉里出现——宽屏顶部本来就有一份同样的。

导航一项都没少，只是不再需要靠滚动去找。入口数按角色与部署不同：完整管理端
19 项，未接入授权中心时 17 项（`授权` / `控制中心` 不渲染），创作者账号 3 项。

### 存量归类说明

88 份存量问卷是按标题模式做的一次**确定性归类**（例如标题写了「成人大学」
的三章会一起落到情景剧情，不被「调教／羞辱」抢走）。这是**起点不是结论**：
分错的成本很低（单条改或勾选批量改），漏掉的在管理端一眼可见。
目前 88/88 全部归类，0 份未分类。

## 三、安全：参与者身份令牌升级到 v2

这一节写给关心数据安全的人，普通用户可以跳过。

**问题**：Telegram 按钮里的问卷链接带一个 `pt=` 签名令牌（30 天有效），
代表「链接是谁的」。旧版前端把它写进 **localStorage 并永久复用**。后果是：
只要一个人把问卷链接转发出去，之后任何人在**同一台浏览器**打开它，都会
以那个人的身份答题、续答，甚至写进对方的进行中答卷。

**已经发生并被处置了**：2026-10-15 至 10-17 期间，账号 1 名下出现 14 个
不同运营商 IP 的设备指纹，而账号主人确认一份都没填过。处置记录完整保存在
[`db/incidents/2026-10-17-user1-token-detach.json`](../../db/incidents/2026-10-17-user1-token-detach.json)：
18 份已完成答卷与 45 份进行中答卷从该账号解绑、10 个结局解锁与 6 个成就删除、
金币账本保持只增不改（不篡改流水）、并提供逐条可执行的回滚语句。

**现在的做法**：

- 令牌只活在**内存 + sessionStorage**：同一标签页刷新仍能续答，关掉标签页即失效。
- 参数被读取后立刻从地址栏**剥离**（`history.replaceState`），你复制出去的
  链接不带任何身份信息。
- 旧 localStorage 键做一次性清除，不会残留。
- 令牌带版本号，客户端预检与服务端吊销判定同一份常量，不各说各话。

## 四、修复项

### 1. 问卷统计的环形图：圆心数字跑到画布外

现象是圆心的「88」贴着顶部标签、甚至有一半被裁掉。根因是圆心文字的定位
写法用了 CSS `calc()`——**ECharts 的 graphic 定位不接受 `calc()`**，值被丢弃后
两个 text 元素全部归位到原点，于是数字、「总计」、顶部扇区标签三层叠在一起。

改成一个零半径饼图系列 + `label.position: "center"`，由 ECharts 自己把文字落在
`series.center` 上。三档屏宽加 150px 矮图都实测过，圆心误差 ±1.5px。

### 2. 页脚「投稿机器人 投稿机器人，投稿给我」

生产配的投稿入口是**网页**（`/submit`）而不是 t.me 机器人，旧解析器匹配不到
机器人用户名就回落成「投稿机器人」，而调用方文案里已经写死了这四个字。

现在解析器返回**目标本身**：`t.me/x → @x`，其他网址 → 域名，未配置 → 整块不渲染。

| 配置                         | 之前                            | 现在                   |
| ---------------------------- | ------------------------------- | ---------------------- |
| `https://emoemok.top/submit` | 投稿机器人 投稿机器人，投稿给我 | 网页投稿 · emoemok.top |
| `https://t.me/xxxbot`        | 投稿机器人 @xxxbot，投稿给我    | 不变（本来就对）       |
| 未配置                       | 显示半截文案                    | 整块不渲染             |

### 3. 广场翻页重复追加

见 §一「🃏 广场往下滑」。根因是拿 React state 当并发闸门——state 要到下一帧
才可见，同一帧的两次回调都放行。改成 ref 同步闸门 + 按编号去重。

这个 bug 是被一条**偶发失败的浏览器测试**逼出来的：它原本只表现为「4 并发下
视觉对比偶尔红一条」，探针一挂才发现不是测试不稳，是产品在重复渲染。

### 4. 侧栏被页面撑出屏幕

工单说的是「矮屏装不下」，量下来是另一回事：侧栏 `position: static`，
高度被正文拉到 1118px，而导航容器 `scrollHeight === clientHeight`——
**导航自己没有滚动**，整页在滚。所以加滚动条是没有意义的，
先把侧栏收成一个视口框（`sticky` + `100dvh`），再谈折叠。

同一轮还量出了另一个结论：按**宽度**判断「要不要收「更多」」是错的。
1024×768 横屏进入的是带文字的完整侧栏，并不是图标轨；
真正的约束是**高度**。现在阈值按高度定，鼠标 860px、触屏 1000px。

### 5. 视觉对比偶发失败（测试侧）

总览/统计的环形图有约 1 秒的进场动画，而截图用例只等 250ms。
实测同一页面在 120ms 时是 38 条 SVG path、1620ms 时是 46 条——它还在长。

给截图用例声明 `reducedMotion: "reduce"`，图表自己会把动画关掉，首帧即终态，
173 张基线随之重拍。**这不是把测试改绿**：它让被测艺术品的状态变成确定的，
而真正的产品缺陷（上面第 3 条）是被它暴露出来的。

## 六、已知限制

- ⚠️ **分类是启发式初分**。88 份按标题模式归类，语义模糊的卷可能落错抽屉。
  这需要人扫一遍，管理端改起来很快。
- 环形图圆心在极窄视口（≤320px）下与「总计」两行间距约 6px，不影响阅读但偏挤。
- 认证卡照片不持久：刷新页面后需要重新上传（这是「照片不出浏览器」的代价）。
- 分类的计数由前端按**过滤后**的列表自算，服务端不返回 count——否则会出现
  「分类显示 12 份、点进去 3 份」（未确认 18+ 时成人条目被服务端过滤）。
- 侧栏的**折叠与紧凑模式按窗口高度判定**，浏览器缩放会改变判定结果；
  这是有意的（缩放后可用高度本来就变了）。
- **真机 iPad 未实测**。WebKit 引擎的 30 条断言覆盖了内核差异，但真机 Safari
  的地址栏收起动画、旋转后 `dvh` 重算、iOS 惯性滚动都不在覆盖范围内。

## 七、部署与回滚

```bash
# 部署（0087 由 wrangler 的迁移记录约束，不会重复 apply；
#  其中归类语句本身可安全重跑——只填 category_id 为空的行走）
cd /home/emo/code/telegram-bot && pnpm deploy

# 回滚应用代码到上一个版本
npx wrangler rollback

# 回滚数据库（若需彻底撤销分类）
# —— 外键是 ON DELETE SET NULL，删表不会带走问卷
DROP INDEX IF EXISTS idx_surveys_category;
DROP TABLE IF EXISTS survey_categories;
# surveys.category_id 列保留也无害（全部为空 = 未分类）
```

晚间那次发布**不含任何数据库变更**，`wrangler rollback` 即可整包退回上午的
`0691fe55`，不需要动数据。

参与者令牌的事故回滚语句在
[`db/incidents/2026-10-17-user1-token-detach.json`](../../db/incidents/2026-10-17-user1-token-detach.json)
的 `restore` 字段，逐条列出答卷 ID、任务运行 ID、被删成就与结局。
