# 部署服务人员操作说明

## 1. 角色边界

你是**部署服务人员**，负责帮助项目方为客户开通 Telegram 多媒体问卷服务。

项目架构由项目方统一管理：

客户
↓
客户 Cloudflare Worker
↓
项目方 Control Plane / Web Admin
↓
Deployment Runner

你的工作入口是 **Web Admin**。

你不负责维护项目源码，也不负责管理项目方的 Cloudflare、Runner 或授权中心。

## 2. 部署前需要客户提供

必须取得：

- 客户名称
- 客户管理员 Telegram 数字 ID
- Telegram Bot Token
- 客户 Cloudflare Account ID
- 客户 Cloudflare API Token

管理员 Telegram ID 示例：

123456789

多个管理员：

123456789,987654321

不要接受 @username 代替数字 ID。

## 3. 打开控制中心

当前生产地址：

https://telegram-multimedia-survey-bot.pd2335346.workers.dev/admin/control

进入：

**控制中心 → ＋ 新建客户**

## 4. 创建客户

填写：

### 客户名称

填写实际客户名称。

### 客户管理员 Telegram ID

填写客户提供的数字 ID。

### 授权天数

按客户购买周期填写。

常规月付填写：

30

### Telegram Bot Token

填写客户通过 BotFather 创建的 Bot Token。

### Cloudflare Account ID

填写客户自己的 Account ID。

### Cloudflare API Token

填写客户为本次部署准备的 API Token。

**不得填写项目方自己的 Token。**

### Worker Name

通常留空。

让系统自动生成可以避免名称冲突。

填写完成后点击：

**创建并部署**

## 5. 部署过程中

点击后不要重复点击「创建并部署」。

系统会创建：

1. License
2. Customer Deployment
3. Deployment Task

随后 Deployment Runner 会自动领取任务并执行：

1. 创建客户 Worker
2. 创建 D1
3. 创建 KV
4. 创建 Queue
5. 执行数据库 migration
6. 部署 Worker
7. 设置 Telegram Webhook
8. 设置 Bot Commands
9. 注册 Worker
10. 等待 Worker 心跳

在页面等待任务状态变化。

## 6. 成功条件

同时确认：

**Deployment Task：succeeded**

以及：

**Customer Worker：online**

并确认页面出现：

- Worker URL
- 版本
- 最近心跳
- 授权到期时间

## 7. 基础验收

打开：

https://<worker>.workers.dev/health

然后使用 Telegram：

1. /start
2. 管理员执行 /create
3. 创建测试问卷
4. 发布问卷
5. 普通账号执行 /surveys
6. 完成填写
7. 查看答卷
8. 执行导出

完整链路必须至少成功一次：

创建 → 发布 → 填写 → 查看 → 导出

## 8. 交付给项目方

发送：

- 客户名称
- Worker URL
- Worker 名称
- Installation ID
- 部署结果
- 验收结果
- 必要的错误日志

如果需要完整部署清单：

deployment-manifest.json

## 9. 敏感信息处理

以下内容不得转发给第三方：

- Bot Token
- Cloudflare API Token
- 项目方 Runner Token
- 项目方 Cloudflare Token
- LICENSE_ADMIN_TOKEN
- 其他客户 License Key
- .customer-secrets.tmp

特别注意：

**客户 Token 属于客户；项目方 Token 属于项目方。不要混用。**

## 10. 续费

部署人员不处理续费。

客户续费由项目方在 Web Admin 控制中心完成：

**客户详情 → 续费 30 天**

续费不会重新部署。

不需要：

- 重建 Worker
- 重建 D1
- 重建 KV
- 重建 Queue
- 重新设置 Webhook
- 重新生成授权密钥

## 11. 暂停与恢复

客户暂停、恢复、禁用等授权操作由项目方处理。

不要通过删除 Worker 或重新部署来实现停用。

## 12. 升级

客户升级由项目方在控制中心发起。

如果项目方要求你进行升级后的验收，只需要按照第 7 节重新测试。

不要删除客户现有资源。

## 13. 部署失败

出现失败时：

**不要删除客户 Cloudflare 资源。**

在控制中心打开失败任务，记录：

- Task ID
- 错误信息
- Runner Log
- Worker 名称
- 失败步骤

然后交给项目方处理。

不要自行修改数据库 migration、部署脚本或 Worker 配置。

## 14. Web Runner 不可用

只有项目方明确要求时，才使用本目录：

客户部署包/

备用人工部署流程：

00-安装依赖.cmd
↓
npx wrangler login
↓
02-正式部署.cmd

人工部署时必须使用客户自己的 Cloudflare 账号。

详细说明见：

客户部署包/README.md

## 15. 禁止事项

不要：

- 使用项目方 Cloudflare Token 登录客户账号
- 把一个客户的 API Token 用到另一个客户
- 删除客户 D1/KV/Queue 后重新部署
- 手工修改生产数据库
- 修改部署包源码后直接部署
- 把 Token 发到群聊
- 把 Token 截图发给项目方以外的人
- 为了解决失败而重复创建多个 Worker

## 16. 标准工作流

完整流程只有：

客户资料
→ Web Admin
→ 新建客户
→ 创建并部署
→ 等待 Runner
→ Worker Online
→ Telegram 验收
→ 回传部署结果

遇到异常：

**保留现场 → 记录错误 → 联系项目方。**
