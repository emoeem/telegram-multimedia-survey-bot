# 部署服务人员：三步完成

本目录可直接交给部署人员。全程使用客户自己的 Cloudflare 账号；你不需要、也
不能索取厂商的 `LICENSE_ADMIN_TOKEN`。

部署前向项目所有者通过安全渠道取得：客户名称、管理员 Telegram 数字 ID、
Telegram Bot Token、授权密钥。管理员 ID 是一串数字，不是 `@用户名`。

## 第 1 步：安装

打开 `客户部署包`，双击 `00-安装依赖.cmd`。若提示没有 Node.js，安装 Node.js
LTS 后重新双击。

## 第 2 步：登录客户 Cloudflare

在 `客户部署包` 空白处按 Shift 并右键，打开 PowerShell，执行：

```powershell
npx wrangler login
```

浏览器会打开。让客户登录并同意授权，看到命令完成后关闭浏览器即可。没有浏览器
登录条件时，可在部署脚本最后一项粘贴客户的临时 Cloudflare API Token；完成后由
客户自行撤销。

## 第 3 步：部署

双击 `02-正式部署.cmd`，按顺序输入或粘贴：

1. 客户名称。
2. 管理员 Telegram 数字 ID。
3. Cloudflare Account ID。已使用浏览器登录时可以直接回车。
4. 项目所有者给出的授权密钥。
5. Telegram Bot Token。
6. Cloudflare API Token。已使用浏览器登录时直接回车。

脚本会自动创建 D1、KV、Queue，部署 Worker，设置 Telegram Webhook。窗口显示
“部署完成”后，向 Bot 发送 `/start`；管理员再创建一个两题测试问卷并发布。将
`customer-deployments\...\deployment-manifest.json` 回传项目所有者。

## 只在出错时看这里

- Node.js 不存在：安装 Node.js LTS，重新运行第 1 步。
- Cloudflare 拒绝：重新运行 `npx wrangler login`，确认登录的是客户账号。
- 缺少授权密钥：联系项目所有者发放密钥；不要索取管理令牌。
- 部署中断：用同一个 `customer-deployments` 目录重新双击 `02-正式部署.cmd`，
  脚本会复用已创建的资源。
- `/start` 没有响应：打开部署结果中的 `Worker URL/health`；若正常，把完整错误
  和 `deployment-manifest.json` 发给项目所有者。

需要预先检查时，双击 `01-预演部署.cmd`。PDF 导入、升级和更多故障处理见根目录
的完整技术说明；它们不属于首次部署必做步骤。
