# 项目所有者内部操作说明

## 1. 授权中心初始化

厂商自己的 Worker 部署完成后，只执行一次：

```bash
bash delivery/02-给项目所有者/00-初始化授权中心.sh
```

本地会生成：

```text
.license-admin.env
```

这个文件是最高敏感级别资料，不得发送给客户或部署人员。

## 2. 新客户

每个客户先创建一个限时授权：

```bash
bash delivery/02-给项目所有者/01-一键发放授权.sh
```

月付客户输入：

```text
30
```

这意味着客户获得 30 天使用期。

## 3. 给部署人员什么

必须通过安全渠道发送：

```text
客户名称
管理员 Telegram 数字 ID
Telegram Bot Token
授权密钥
```

再发送：

```text
delivery/01-发给部署服务人员/
```

不要发送厂商管理令牌。

## 4. 部署完成后

要求部署人员回传：

```text
deployment-manifest.json
Worker URL
验收结果
```

检查：

- Worker URL
- Installation ID
- 授权编号
- 部署版本
- D1/KV/Queue
- Telegram Webhook
- 基础问卷流程

## 5. 月度续费

客户付款后，在**厂商授权中心 Bot**发送：

```text
/license_extend <授权编号> 30
```

例如：

```text
/license_extend LIC-260815-ABCDE 30
```

然后：

```text
/licenses
```

检查新的到期日期。

### 为什么不需要重新部署？

许可证保存在厂商授权中心。

客户 Worker 定期向授权中心验证：

```text
客户 Worker
    ↓
LICENSE_SERVER_URL
    ↓
厂商授权中心
    ↓
授权状态 / 到期日期
```

因此续费只是修改授权中心中的到期时间。

## 6. 过期

客户没有付款：

- 不需要删除客户 D1
- 不需要删除客户 Worker
- 不需要登录客户 Cloudflare
- 不需要重新部署

限时授权到期后，授权检查会阻止客户继续正常使用。

## 7. 临时停用

```text
/license_suspend <授权编号>
```

恢复：

```text
/license_resume <授权编号>
```

永久作废：

```text
/license_revoke <授权编号>
```

revoke 不可恢复，慎用。

## 8. 永久授权

如果以后销售永久版本：

```text
/license_create perpetual forever 1 客户名称
```

永久授权本身不等于永久获得所有新版本。

升级权益通过：

```text
/license_updates <授权编号> <天数|forever>
```

管理。

## 9. 客户资料

每个客户建立一份记录：

```text
客户名称
授权编号
Worker
Installation ID
版本
到期时间
激活数
付款记录
升级记录
验收记录
```

不要在普通文本记录里保存：

- Bot Token
- Cloudflare Token
- LICENSE_ADMIN_TOKEN
- 明文授权密钥
