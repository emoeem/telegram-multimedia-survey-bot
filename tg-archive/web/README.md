# tg-web-archive（Web 视图层归档 MVP）

在官方 web.telegram.org 页面内运行的用户脚本，把当前聊天归档到你自己的私有频道，
**不需要 api_id/api_hash**。设计见 `docs/WEB_VIEW_ARCHIVE_MVP.md`。

## 快速开始

1. 浏览器安装 Tampermonkey（或 Violentmonkey）。
2. 新建脚本，粘贴 [tg-web-archive.user.js](./tg-web-archive.user.js) 内容并保存。
3. 打开 web.telegram.org/a（或 /k）并扫码登录。
4. 页面右下角出现「归档助手」面板（收起后点右下角 🗂 悬浮球可恢复，或用
   Tampermonkey 菜单「显示面板」）：
   - 目标频道：填你自己频道的名字（需在左侧会话列表可见，建议置顶）。
   - 模式：`snapshot`（气泡截图，默认推荐）/ `copy`（文字重发）/ `forward`（原生转发，实验性）。
   - 保护策略：`skip`（默认）/ `text_only` / `allow_media`。
   - 起始日期（可选）：早于该日期的消息跳过并标记，不再重扫。
   - 设置行：截图倍率（1x/2x/3x）、格式（PNG/JPEG）、每条发送间隔（秒，默认 1.2）。
5. 先点「① 探测 DOM」，把输出复制回来校准（Web 改版后同样用它）。
6. 选择源聊天，点「⚡ 截图到最新」或「▲ 向上回溯」。

## 三种模式

- `snapshot`（默认推荐）：把每条消息气泡截成 PNG 发进频道，一图带发送者/时间/可见
  媒体，caption 带 `#media_图片 #date_2026_09_08 #chat_群名 #user_某人 #m_…` 等标签，
  便于在频道里按类型/日期/来源检索。相册（同一组的多张图）整组截一张，不会拆成孤立截图。
  受保护聊天也能截（屏幕上能看到的才会进归档；若不希望归档受保护内容，请不要在该聊天运行）。
- `copy`（实验阶段）：读取消息文字（群聊自动带发送者前缀）后到频道输入框粘贴发送。
  纯媒体消息在 `skip`/`text_only` 策略下按策略**有意跳过并标记**（不会进失败队列）；
  `allow_media` 开启时才用 `stream/…` 地址分片取回 Blob 注入输入框发送
  （思路参考 [Neet-Nestor/Telegram-Media-Downloader](https://github.com/Neet-Nestor/Telegram-Media-Downloader)）。
- `forward`（实验性）：调用页面原生「转发」对话框把消息原样转进频道，保真度最高。
  需要真机校准选择器；右键菜单没有「转发」的消息（受保护聊天）按策略自动跳过并标记。

## 发送可靠性与幂等（0.5.0）

- **发送成功判定**：输入框被清空 **且** 频道里出现新消息（气泡签名变化）才记成功；
  断网/发送失败时条目进重试队列而不是被误标成功。
- **幂等标记**：snapshot 的 caption 末尾带 `#m_<peer>_<mid>` 唯一标记；发送前若发现
  频道里已有同标记消息，直接跳过并记 done——重跑同一条不会产生重复归档。
- **重试队列**：元数据持久化（刷新页面不丢），重试时自动切到归档频道并校验目标 peer
  才发送，截图类先回源聊天按消息 id **重新截图**（找不到的消息留队，连续 3 次自动放弃）。
  队列徽标按错误类型（capture/attach/upload/send/switch/forward-*）分类显示。

## 流式使用（0.5.0）

1. 模式选 snapshot（默认）；填归档频道；打开源聊天：
   - 「⚡ 截图到最新」：从当前位置向下，**截图一张 → 自动切到归档频道发一张 → 自动切回**，
     到最新自动停；
   - 「▲ 向上回溯」：从底部向上补历史。判重按「每个聊天独立的已处理名单」，已归档的
     消息自动跳过；开始产出后连续遇到已处理消息即认为到达上次边界自动停，可以反复点。
2. 运行中面板实时显示进度（当前 mid、成功/失败/跳过数）；「停止」跑完当前一条后暂停，
   下次从断点继续。结束时按类型/错误汇总。
3. 内存中任意时刻只有 1 张截图；失败项的**元数据**进入重试队列（脚本重载后会自动恢复）。
4. 点「重试队列」：脚本**自动切换到归档频道并校验目标 peer** 后才发送，不会发错聊天；
   发送前会回到源聊天按消息 id 重新截图（找不到的消息留队，连续 3 次失败自动放弃）。
   「清理队列」清空。
5. 「重置进度」会清空当前聊天的断点与已处理名单（弹确认框），已归档过的消息重跑会再发一遍，
   仅在想完全重跑某聊天时使用。

### 进度模型（0.5.0）

- `done:<peer>`：每个聊天独立的“已归档/有意跳过”消息 id 名单，是所有方向的判重依据。
  发送动作发生在归档频道里，但记录时显式带源聊天 peer，不会串。
- `check:<peer>`：向下方向的“高水位”断点（已发送的最大 mid）。「向上回溯」不用它做
  停止条件，因此补老历史不会被它卡住。
- 判断一条是否成功发送：轮询确认输入框真的被 Telegram 清空（最多约 9 秒），减少
  “已发出却当失败、重试重复发送”的竞态。

若自动切换频道失败，先跑「① 探测 DOM」，把 `sidebarRows:` 那行发回来校准。

## 目录

- `tg-web-archive.user.js` —— 单文件用户脚本（探测优先骨架）。

## 安全提示

- 只在你自己的、有权这样使用的聊天上运行；
- 受保护内容默认策略为 skip（copy 模式不发媒体）；`allow_media` 是高风险开关，绕过
  对方保存限制，账号风险自负；snapshot 模式截取的是屏幕可见内容，受保护聊天是否使用
  请自行确认权限；
- 页面必须保持打开，脚本随 Telegram Web 改版可能失效——遇到失效先跑「探测 DOM」。
